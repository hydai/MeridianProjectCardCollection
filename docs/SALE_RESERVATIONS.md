# 出售預約

流程為 **待售 → 預約出售 → 已售出**；取消出售預約則恢復待售。

## 操作

1. 在「卡片管理」將卡片設為待售，或使用批次上架。
2. 開啟後台「交易 → 出售預約」。搜尋卡片、輸入各款張數和約定單價，
   填寫預約日期、買家與備註後建立。每筆最多 100 張；買家和備註選填。
   卡片管理的個別待售卡也提供「預約出售」，可快速建立單張預約。
3. 約定期間，卡片仍計入收藏，但不再提供出售或交換。公開看板顯示
   可售張數與「預約出售」張數；買家、約定價格及預約備註僅後台可見。
4. 交易完成後按「完成出售」，核對成交日期、張數和總額，再確認。
   系統會將整筆卡片列為已售出，並記錄每張的約定成交價。
5. 交易取消則按「取消預約」並確認；卡片恢復原本的待售價格與備註。

一筆預約整筆完成或取消。需要分次處理的卡片請建立不同預約。
已經當場成交的交易仍可使用卡片管理的「賣出」直接記錄。
建立、完成與取消的紀錄可在「痕跡」查詢；完成的出售也會進入交易歷史。

## 資料與部署

- `sale_reservations` 保存買家、日期、備註及 pending/completed/cancelled 狀態。
- `sale_reservation_lines` 固定實體 card ID、catalog ID 與約定單價。
- `pending_sale_cards` view 提供目前的實體卡鎖定；出售與交換共用可用庫存檢查。
- `cards.status` 在預約期間維持 `for_sale`，完成時才變成 `sold`。
- 建立與結束預約都以 D1 batch 執行；寫入時重新核對卡片版本和預約狀態，
  整筆成功或整筆拒絕，重複完成／取消不會產生第二筆成交。
- 後台 API 為 `/api/admin/pending-sales`，提供 GET/POST、
  `POST /:id/complete` 與 `DELETE /:id`，沿用 owner-only Access 保護。
- 公開 market DTO 僅增加 `reservationType`；overview 的 `reserved` 是出售與交換
  預約的總量，因此統計顯示通用「預約中」。

部署前先依 [備份流程](BACKUP.md) 建立並驗證正式站備份，再套用
`0022_sale_reservations.sql`，最後部署程式。此 migration 僅新增資料表、索引及 view，
不會變更現有卡片或交換預約。備份工具會依來源 schema 加入出售預約表的數量檢查，
亦可讀取尚未有這兩張表的舊備份。

# 批次上架

## 操作流程

在後台「收藏 → 卡片管理」依彈數、系列、角色、稀有度、狀態篩選後，開啟「批次上架」。面板只提供篩選內 `owned`、未保留、未被新舊交換預約占用的卡片；同款合併顯示可上架張數。

每款輸入張數（0 代表不選），支援單款全部、全部填滿、清空數量。一批統一設為待售或待換，售價為每張價格，空白代表面議；交換條件空白代表開放出價。不同價格或條件可分批上架。每批最多 100 張，超限會提示並停用預覽。

預覽列出卡種、張數、總量、上架方式與公開條件，確認後送出。成功顯示上架張數並更新管理清單；前台沿用交易看板與待換公告候選清單。庫存衝突或結果不明時停止重送，要求重新整理並重新選擇數量。已成功但清單更新失敗會保留成功提示，僅重試讀取庫存。

## 一致性

同款按實體卡 ID 由小到大選取，預覽固定具體 ID 與預期卡位。API `POST /api/admin/cards/batch-listing` 接收 `status`、`cards: [{cardId, catalogId}]` 及選填的 `askingPrice` / `wantInReturn`，只允許從 owned 新上架，不改動已上架卡的條件。

後端驗證數量上限、ID、重複卡、價格與文字型別，讀取卡片版本。沿用 `unchangedCardsCondition` 和 `CARD_IS_UNRESERVED`，在 D1 batch 內先以所有卡的版本及資格建立活動事件，再以事件存在作為更新及活動明細的共同條件。任一卡不存在、改了卡位、已售出、上架、保留或預約，整批不寫入。

卡片更新和一筆 `card_classified` 活動（每卡種一行，包含數量、前後狀態與條件）同一交易完成，不需資料庫遷移。保留原卡片備註；待售清除舊交換條件，待換清除舊售價。請求固定實體卡，重送不會選到其他副本。

## 驗證

- API：待售／待換、選取數量與公開結果、輸入驗證、無資格及舊式預約、重送、100 張邊界。
- 競爭：檢查後有卡被保留、預約或更新，整批無部分寫入或多餘活動。
- UI：篩選、排除不可用卡、數量與價格驗證、預覽、返回、一次提交、衝突重新選擇、成功後更新失敗。
- 既有測試、型別檢查、格式檢查、建置與桌面／手機瀏覽器檢查。
